# GPU Task Dispatcher

Единый брокер для сервисов, совместно использующих один или несколько GPU: IZ.Scribe,
Privacy Gateway и будущие локальные приложения. Проект включает диспетчер
задач и веб-панель мониторинга.

## Возможности

- параллельное выполнение независимых задач на разных GPU без переполнения VRAM;
- автоматическая выгрузка Whisper перед Qwen и Qwen перед Whisper;
- ограниченное пакетирование однотипных LLM-запросов;
- эксклюзивное выполнение всех GPU-этапов одной бизнес-задачи без чередования
  с задачами других сервисов и с закреплением за одним GPU;
- внешний ID задачи из интерфейса вызывающего сервиса;
- очередь, активная задача, время ожидания и выполнения;
- остановка активных и ожидающих задач прямо из веб-панели;
- постраничная история с фильтрами по ID, сервису, нагрузке и статусу;
- отдельная страница сохранённых запросов и ответов для каждого LLM-вызова;
- монитор GPU, VRAM, CPU, RAM, дисков, Docker и загруженных моделей;
- SQLite-журнал на большом разделе `/srv`;
- подключение новых сервисов без изменения диспетчера.

## Порты

- `11435` — совместимый прокси Ollama/Whisper и API очереди;
- `9999` — веб-панель.

Внутренние worker-сервисы используют отдельные порты для каждого слота,
например Ollama `11434`/`11436` и Whisper `8000`/`8001`. Клиентские сервисы
по-прежнему обращаются только к брокеру на `11435`.

## Запуск

```bash
cp .env.example .env
# задайте длинный GPU_DISPATCHER_TOKEN
sudo mkdir -p /srv/data/gpu-task-dispatcher
docker compose up -d --build
```

Проверка:

```bash
curl http://127.0.0.1:11435/health
curl http://127.0.0.1:11435/queue
curl http://127.0.0.1:9999/
```

## Подключение сервиса

Вместо прямого Ollama/Whisper используйте `http://HOST:11435` и передавайте:

```text
X-GPU-Service: privacy-gateway
X-GPU-Source-ID: de7cbf72-90ed-45e6-a31a-384efc9c2819
```

`X-GPU-Source-ID` — ID задания, который видит пользователь в исходном
сервисе. Для IZ.Scribe это ID записи, для Privacy Gateway — ID из страницы
«Все задания». Все подзапросы одной бизнес-задачи должны использовать один ID.
Диспетчер удерживает очередь за сочетанием `X-GPU-Service` и
`X-GPU-Source-ID`, пока от этой задачи поступают новые GPU-запросы. После
последнего запроса владение освобождается через `GPU_TASK_IDLE_SECONDS`
(по умолчанию 10 секунд). Если сервис точно знает, что отправляет последний
GPU-запрос задачи, он может добавить `X-GPU-Task-Final: true` и освободить
очередь сразу после ответа.

## Несколько GPU

Слоты задаются переменной `GPU_WORKERS_JSON`. Каждый слот содержит логический
ID, отображаемое имя и адреса независимых Ollama/Whisper:

```json
[
  {"id":"gpu-1","label":"Primary GPU","ollama_url":"http://127.0.0.1:11434","whisper_url":"http://127.0.0.1:8000"},
  {"id":"gpu-2","label":"Secondary GPU","ollama_url":"http://127.0.0.1:11436","whisper_url":"http://127.0.0.1:8001"}
]
```

Брокер выполняет по одному запросу на каждом слоте. Все LLM/STT-запросы одной
бизнес-задачи остаются на исходном слоте до её завершения. Независимая задача
может одновременно выполняться на другом GPU.

Физические карты привязываются к worker-сервисам через
`CUDA_VISIBLE_DEVICES`/`GPU_SLOT_*_DEVICE`, а не зашиваются в код. При замене
карты достаточно изменить UUID и подпись слота, затем пересоздать только
соответствующие Ollama/Whisper; клиентские адреса и брокер не меняются.

Шаблон systemd для экземпляров Ollama находится в
`deploy/ollama-gpu@.service`. Контейнеры Whisper запускаются профилем:

Текущие серверные UUID хранятся в `deploy/ollama-gpu-1.env` и
`deploy/ollama-gpu-2.env`. При замене карты меняются только UUID в файле слота
и соответствующая переменная `GPU_SLOT_1_DEVICE` либо `GPU_SLOT_2_DEVICE`.

```bash
docker compose --profile gpu-workers up -d whisper-gpu-1 whisper-gpu-2
```

Поддерживаемые маршруты проксируются без изменения формата тела:

- Ollama: `/api/chat`, `/api/generate`, `/api/tags`, `/api/ps`;
- Whisper: `/v1/audio/transcriptions`;
- состояние: `/health`, `/queue`.
- управление: `POST /queue/{internal_job_id}/cancel` с заголовком
  `X-GPU-Dispatcher-Token`.

## Добавление нового сервиса

1. Направьте его GPU-запросы на порт `11435`.
2. Передавайте стабильное имя в `X-GPU-Service`.
3. Передавайте пользовательский ID задания в `X-GPU-Source-ID`.
4. По `/queue` сопоставляйте `active.source_id` и `pending[].source_id`.
5. Не используйте внутренний ID вызова как бизнес-ID.

## Безопасное переключение моделей

Перед запуском Whisper диспетчер выгружает Qwen только на назначенном GPU,
дожидается пустого `/api/ps`
и выдерживает дополнительную паузу для освобождения CUDA-контекста драйвером.
Пауза задаётся `GPU_OLLAMA_RELEASE_DELAY_SECONDS` и по умолчанию равна четырём
секундам. Сам Whisper дополнительно повторяет загрузку модели при кратковременной
ошибке `cudaErrorDevicesUnavailable`.

## Хранение

Журнал по умолчанию находится в
`/srv/data/gpu-task-dispatcher/dispatcher.db`. Docker также рекомендуется
держать на `/srv/docker`. Секреты и токены в Git не сохраняются.
По умолчанию сохраняются последние 100 000 завершённых задач; лимит меняется
переменной `GPU_JOB_HISTORY_LIMIT`. Активные и ожидающие задачи лимитом не
удаляются. Текстовые тела LLM-запросов и ответов хранятся в SQLite в сжатом
виде. Текстовые JSON-ответы Whisper с расшифровкой также сохраняются, но
бинарные аудиозапросы в журнал не копируются. Максимальный размер каждой
сохранённой стороны задаётся
`GPU_JOB_PAYLOAD_MAX_BYTES` (по умолчанию 512 КиБ).

## Обновление без потери журнала

```bash
docker compose build
docker compose up -d
```

Перед обновлением сделайте копию каталога `/srv/data/gpu-task-dispatcher`.
Активный HTTP-запрос при перезапуске не возобновляется автоматически; вызывающий
сервис должен считать его прерванным и решать, требуется ли повтор.
Оставшиеся после перезапуска записи со статусами `queued` и `running`
автоматически переводятся в `cancelled`, потому что соответствующих запросов
в памяти уже нет.
